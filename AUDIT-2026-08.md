### 1. The shared barrel puts every pack's content catalogue in the entry chunk

**FIXED, commit `dc9af7d` (3.2).** 244.57 to 224.96 kB raw, 77.66 to 70.89 gzip. Exports map plus three deep imports; verified by booting the server, not only by typechecking.

**What it is.** `packages/shared/src/index.ts:138-172` is a barrel that `export *`s every
pack engine. Exactly three eager modules import from `@gamenight/shared`, and all three
want one value:

    apps/web/src/api.ts:4              import type { SessionPackKey }       (type only)
    apps/web/src/packs.ts:25           import { SESSION_PACKS, ... }        (runtime)
    apps/web/src/pages/EventPage.tsx:11 import { SESSION_PACKS }            (runtime)

Rollup cannot tree-shake through the barrel cleanly, so the entry chunk currently carries
content none of the eager pages reference. Grepping the built entry chunk finds:

  - the entire Social Deduction title catalogue (Werewolf, Salem, Secret Hitler, Avalon,
    with every faction and role) from `packages/shared/src/deduction.ts`,
  - the full Smash fighter roster (80-plus names) from `packages/shared/src/smash.ts`,
  - the Casino Run modifier catalogue from `packages/shared/src/modifiers.ts`.

**Where.** `packages/shared/src/index.ts:138-172`, consumed at `apps/web/src/packs.ts:25`
and `apps/web/src/pages/EventPage.tsx:11`.

**What breaks if it stays.** Nothing errors. Every first launch, every cold cache after
every deploy, and every TV view downloads and parses three pack content catalogues it will
never read. It gets monotonically worse: this is the mechanism by which the entry grew
from 214.73 kB (2026-07-28, four packs) to 244.57 kB (today, twelve packs), and the next
four packs each add their catalogue to the entry the day they land.

**Measured, not estimated.** Changing only those two import statements to deep-import
`packages/shared/src/packs.js` and rebuilding:

    before   244.57 kB raw / 77.68 kB gzip
    after    224.96 kB raw / 70.87 kB gzip
    delta    -19.61 kB raw / -6.81 kB gzip  (-8.8 percent gzip)

`tsc --noEmit` passed on the experiment. "Secret Hitler" and "Bowser" are absent from the
resulting entry chunk. The experiment was reverted; the tree is clean.

For scale, the rest of the entry decomposes (measured with a throwaway `manualChunks`
probe, since chunk-splitting adds overhead these do not sum exactly):

    react + react-dom + scheduler   155.10 kB raw / 50.18 kB gzip
    react-router + remix router      30.79 kB raw / 11.45 kB gzip
    everything first-party           ~58 kB raw

So 76 percent of the entry is `node_modules` and irreducible without dropping a dependency.
The shared barrel is essentially all of the remaining addressable weight.

**Confidence.** High. Measured twice, with a typecheck.

**Cost to fix.** Two options, both small.

  - *Deep imports at the three call sites.* Two lines change. Needs an `exports` map on
    `packages/shared/package.json` to keep the specifier tidy (`@gamenight/shared/packs`
    rather than a relative path climbing out of `apps/web`), which touches server
    resolution and must be verified against `tsc` in all four packages plus the `tsx`
    test runner. Roughly an hour with verification.
  - *Split the registry out of the barrel entirely,* so `packs.ts` is never reachable via
    `index.ts`. Larger blast radius, no better result.

Recommend the first. It is also the only fix that generalises: any future eager import of
a shared value gets the same protection for free.

### 3. The format breakdown sorts six of twelve formats to the top by accident

**FIXED, commit `c7f4eab` (3.1).** `formatOrderIndex` also sends an unknown format to the bottom rather than the top, which was the half of the bug that was backwards rather than missing.

**What it is.** `apps/server/src/stats.ts:101`:

    const FORMAT_ORDER = ["free", "ffa", "grandprix", "bestof", "koth", "board", "other"];

and `stats.ts:106` sorts with `FORMAT_ORDER.indexOf(a[0]) - FORMAT_ORDER.indexOf(b[0])`.

`indexOf` returns -1 for anything absent. Six live format keys are absent: `smashdown`,
`cash`, `boardgame`, `cardtable`, `deduction`, `casino_run`. All six therefore sort at -1,
which is *ahead of* `free` at index 0.

**What breaks if it stays.** On the crew stats screen, the casino group's Cash game bucket,
Board Game, Card Table, Social Deduction, Casino Run and Smashdown all appear above
Free Play in the per-game format list, in arbitrary relative order. `"other"`, which the
array clearly intends as the trailing bucket, sorts last only among the seven it lists and
is beaten to the top by every unknown. Nothing errors and no number is wrong; the ordering
is.

**Confidence.** High. Read directly; the semantics of `indexOf(-1)` are not in doubt.

**Cost.** The narrow fix is one line (map missing keys to `Infinity`, or complete the
array). The right fix is the same one as SHOULD FIX 1: this list and `FORMAT_LABEL` are
two hand-maintained tables keyed by the same thing, on opposite sides of the wire.

## NOTED

True, verified, and probably not worth the churn.

### 1. Dead schema columns

  - **`matches.advances_to_match_id`** (`schema.ts:272`) is completely dead. It appears
    nowhere else in the repository: never written, never read, never referenced by a test.
    Brackets derive advancement from the shared engine rather than storing it. Dropping a
    column is a destructive migration for zero runtime benefit; a comment marking it dead
    costs nothing and is the honest option.
  - **`match_participants.seed`** (`schema.ts:290`) is write-only. Written at
    `brackets.ts:354`, read nowhere. Bracket seeds are recomputed from `brackets.entrants`
    on every read. Harmless, and arguably worth keeping as ledger provenance.

### 2. 168 exported names with no importer, and why the linter will not find them

A resolver-accurate scan (handling shared's `export *` barrel and the server's `.js`
import extensions) finds 168 exported symbols referenced in no other file. Almost none of
it is dead code. The overwhelming majority is over-exporting: a function used only inside
its own module that carries an unnecessary `export`. `apps/web/src/recap.tsx` is
representative, where `computeStandings`, `biggestUpset` and `drawRecapCard` all look dead
and are all called from `drawRecapCard`/`RecapModal` inside the same file.

**The important consequence for phase 4:** TypeScript's `noUnusedLocals` does not flag
unused *exports*. So the flag flip will not touch any of these 168. Do not size phase 4 by
this number.

A genuinely-unused subset worth a look if someone is already in the file:
`apps/web/src/cache.ts` (`dropCache`), `apps/web/src/Skeleton.tsx` (`SkeletonCard`),
`apps/web/src/useTheme.ts` (`readTheme`, `DEFAULT_THEME`, `THEME_STORAGE_KEY`),
`apps/server/src/blackjack.ts` / `craps.ts` / `roulette.ts` / `casinorun.ts`
(`BLACKJACK_PACK`, `CRAPS_PACK`, `ROULETTE_PACK`, `CASINO_RUN_PACK`).

### 3. `index.css` is smaller than it looks, and the per-pack blocks belong where they are

Scoping finding 5's CSS half does not hold up:

    index.css source            80,651 bytes, of which 38,782 (48 percent) are comments
    built entry CSS             78,967 bytes raw / 14,233 gzip
    of which Tailwind's own     the first 45,857 bytes (58 percent) is preflight plus
                                generated utilities; the hand-written .gn-* shell is
                                the remaining ~33 kB

Gzipped the whole thing is 14.2 kB, which is 4 kB less than the JS saving available from
MUST FIX 1 alone.

On splitting the per-pack token blocks out: they should not move. The `--gn-cab-*-edge`,
`-top` and `-ink` tokens (`index.css:910-943`) style the game picker's cabinet tiles, and
the picker renders on Home and EventPage, both of which are on the eager entry path. Moving
those tokens to a lazy stylesheet would either break the picker or force a second
stylesheet request on the entry path, which is a worse trade.

The one genuine inefficiency is that Tailwind v4 scans the whole project and emits
utilities used only by lazily loaded pack pages into the single entry stylesheet. Tailwind
v4 has no per-chunk output mechanism, so there is no fix short of leaving Tailwind, which
is not a cleanup.

### 9. `isRacer` rejects a racer the Mario Kart picker offers (NEW, 2026-08-15)

**Found by `packages/shared/tests/mariokart.test.ts`, written in phase 2.3. Left failing
under a todo marker. Not fixed: outside the approved phase 3 scope.**

**What it is.** A title scopes the racer picker and the random pool (the standing rule for
character packs), so a Double Dash night is offered that title's roster, which includes
`Paratroopa`. `isRacer` (`packages/shared/src/mariokart.ts:23`) checks `MARIO_KART_RACERS`
alone, and that constant IS the MK8 Deluxe roster. So `isRacer("Paratroopa")` is false.
Exactly one racer drifts; every other title's roster is a subset of the master list.

**Why it matters.** `isRacer` is the gate two server paths run a submitted racer through on
the way to the ledger (`mariokart.ts:317` and `:482`), and a rejected name is replaced with
`null` rather than refused, which is this repository's signature failure shape.

**Why it is LATENT rather than live, verified rather than assumed.** Both gates currently
have something that rescues them. `mariokart.ts:482` falls back to `charOf.get(playerId)`,
the slot's stored racer, which was set through the `/character` route, and that route
validates against `rosterForTitle` and accepts Paratroopa correctly. `mariokart.ts:317`
parses the roster at session start, where the shipped client sends names only. So nothing
is wrong on a screen today.

**What would make it live.** A client that starts sending characters at session start, or a
later pass that tidies away the `:482` fallback. Either is an ordinary change that would
look entirely safe.

**Cost to fix.** Small: either widen `isRacer` to the union of every title's roster, or make
the two server sites validate against `rosterForTitle(MARIO_KART_TITLES, state.titleId)` the
way the `/character` route already does. The second is more correct, since it also stops a
Double Dash night accepting an MK World racer.

### ESLint: not needed, and the audit did not find a case for it

The brief asked for a recommendation rather than a unilateral add. The recommendation is
**no**. Everything an ESLint pass would have caught here, the two `tsc` flags already catch
for eleven of eleven cases, at zero dependency cost and zero lockfile risk against Render's
frozen install. The remaining categories the audit turned up (parallel per-pack tables,
hardcoded registry identifiers, over-exports) are repo-specific rules that no stock ESLint
config knows about and that the existing source-scanning tests (`copy-rules.test.ts`,
`pack-screens.test.ts`) already have a proven pattern for.

### Two source-scanning tests worth writing, modelled on `copy-rules.test.ts`

  - **No hardcoded pack identifier outside `packs.ts`.** Scan `apps/server/src` and
    `apps/web/src` for every `ledger`, `gameName`, `keyPrefix` and `wsType` value in
    `SESSION_PACKS` appearing as a bare string literal. It must allow the legitimate sites:
    `packs.ts` itself, the `packConfig` mechanism, `boardgame.ts:32` / `cardtable.ts:24` /

    constants that happen to share a spelling (`boardgame.ts:35`, `cardtable.ts:28`,
    `deduction.ts:90`), and the two non-registry ledgers. Write it after SHOULD FIX 1
    lands, or it fails on arrival.
  - **No parallel lookup table keyed by pack.** Harder to state mechanically. The tractable
    version asserts that every `SESSION_PACK_KEYS` entry appears in the derived tables
    (`FORMAT_LABEL`, `pack-screens.test.ts`'s `SCREENS`, `guest-link.ts`'s adapter lists),
    which turns MUST FIX 2 and SHOULD FIX 2 and 3 into red tests rather than quiet gaps.
    That is a completeness assertion rather than a prohibition, and it is the version worth
    writing.

### A bundle size assertion: yes, with the tradeoff stated

Worth adding, at a threshold with headroom rather than at the current number. The argument
for is exactly MUST FIX 1: the entry grew 14 percent over seven packs and nobody noticed
for a month, because nothing was watching. The argument against is real: it needs bumping
on legitimate growth, and a red gate that is routinely bumped teaches people to bump it
without looking.

The mitigation is to assert on the **gzip** figure (which is what a phone actually
downloads) and to write the current number and the reason into the test's own comment, so
the next person to raise it has to say why in the same commit. Set it after MUST FIX 1
lands, at roughly 75 kB gzip, which leaves about 6 percent of headroom over the post-fix
71 kB.
