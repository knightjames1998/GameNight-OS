## What this project is
GameNight OS: a friend-group game night app, live in production at `gamenightos.app`. The
group is the account; every table is scoped to `group_id`. The framework is BUILT and
deployed. Work now is new game packs, event-layer features, polish and cleanup. Not
foundations.

## How work happens now
All work runs through **Claude Code**, against a real checkout, with a real Node 22 runtime.
The old zip-of-full-file-replacements delivery is retired.

Start of every session:

1. Fresh `git clone --depth 1 https://github.com/knightjames1998/GameNight-OS.git`. Never
   reuse a prior working directory and never work from memory of a prior session.
2. `cat BACKLOG.md`, starting with the MAP STATUS block at the very top.
3. Act on the counter. **The test is what the counter READS when the session starts, never
   what it will read when the session ends.**
   - counter < 3: continue with the requested work, and increment it by 1 in the same commit
     as anything that ships.
   - counter >= 3: say so, then reconcile `BACKLOG.md` and redraw the project map FIRST,
     reset MAP STATUS (date = today, counter = 0), and only then start the feature work.
     Doing it first is the point; a long session that leaves it for the end skips it.
   - The comparison is `>=`, not `=`. The counter has genuinely read 4, because a due redraw
     was skipped on 2026-08-17 and carried forward. An equality test passes silently there
     and the redraw never happens.
   - If James asks to skip a due redraw, log the skip in MAP STATUS naming what would have
     been drawn, and carry the counter FORWARD rather than resetting it.
4. Confirm scope with James in a short structured exchange before writing code.

**Each session gets a written prompt committed to the repo root**, named `SESSION-{name}.md`.
It states the ordered commits, the gates, the decisions already locked and the items
explicitly deferred, so the Claude Code session cannot quietly redefine its own scope.
Prompts are drafted to `/mnt/user-data/outputs/` and committed with the work.

Before every commit, in this order:

```
pnpm install --frozen-lockfile   # if dependencies changed
pnpm -r typecheck                # all four packages must print Done

```

**Record the numbers the run actually printed. Never carry forward a number a previous
session reported.** A commit that has not been typechecked, built and tested is not
finished.

**Claude Code pushes to `main` directly, and a push to `main` auto-deploys to Render.** There
is no review gate between a bad commit and production. The ritual above is the only thing
standing between a refactor and a crash-looping server on a game night, so it is not
optional and it is not skipped when the change "obviously" works.

**A session cannot see the Render dashboard, and must not claim anything about the deploy.**
Say the push landed, state the deploy steps, and stop. Watching the deploy go green is

## Verification harnesses (there IS a browser here)
Five committed harnesses drive headless Chromium over CDP against the REAL built bundle with
a stubbed API. Chromium lives at `/opt/pw-browsers/chromium` and is spawned with
`--headless=new` on a debugging port. Any claim that this environment has no browser is
obsolete and has caused real misses.

- `scripts/tv-fit.mjs`: every TV screen at 1920x1080. Asks two questions, FITS (does the
  layout end inside the screen, measured against the LOWEST PAINTED PIXEL rather than the
  footer) and IS SEEN (is anything still covered by a fixed overlay such as the rail). Exits
  non-zero on a NEW overlap; known overflows are listed in `KNOWN` with their BUGS entry as
  the permanent record. Its back-button hook is `.gn-textbtn, .cg-tv__back, .beerio-tv-back`,
  so a screen with its own styled back button must add its class there or it silently reports
  "no button" and its standing-rule-4 check is skipped rather than failed.
- `scripts/theme-sweep.mjs`: every resolved computed style under both themes, across `ROUTES`
  and `RULE_ROUTES`. `TRACKED_PROPS` covers colour, the four radii, font-family, opacity and
  the background gradient. It does NOT track box-model lengths, so padding and border widths
  are outside what it can see.
- `scripts/screens-baseline.mjs` with `screens-baseline.json`: pins screen TEXT. It cannot
  see a repaint, which is why the theme sweep exists beside it.
- `scripts/felt-variance.mjs` and `scripts/generate-felt-tile.mjs`: the cloth. A tiling
  texture has to be judged at the size the stylesheet paints it, never at 1:1.

A visual change is MEASURED AND RENDERED before it is committed. Click-through and
device-feel verification still happen on-device, and that is the only remaining gap.

  - Server: `pack-runtime.ts` (`createPackRuntime` supplies `roleOf`, `isHostRole`,

  - Client: `usePackSession.ts` (the whole pack-page shell: ctx/session/loading/busy,

    `pages/tv-band.ts`, `beerio/band.ts`.

  chunk), immutable caching on `/assets` with `index.html` never cached, gzip at the origin,
  self-hosted fonts, `/api`-scoped session lookup, `Promise.all` on the multi-query
  endpoints, keep-warm noon to 2am Central.
- **Quick play:** running a mode without a crew silently creates a hidden personal crew
  (`groups.is_personal`), so scoring, TV and recap all work through one system.

- **Stats:** one materialized ledger (`matches` / `match_participants`), fed by every pack on

## Standing rules for EVERY game mode (no exceptions)
1. Owners/admins run the mode: only they start it and edit results. Members watch. A per-mode
   toggle may open scoring to members; it defaults OFF. Gating is enforced SERVER-SIDE.
2. Members join the HOST'S live session, never a local copy. Session state lives server-side,
   keyed to the event. Anything a viewer must not see lives in a SEPARATE STORE, not behind a
   filter: `sessionView` takes no viewer argument, so a secret on session state reaches every
   player and nothing errors.
3. A TV mode, styled in that mode's own design language, not a generic one.
4. A back button on every screen of the mode, including spectator and TV views, AND a way
   back to the event it belongs to. History-based, falling back to home. Never a raw
   `<a href>` for internal navigation: that is a full page load, and iOS standalone turns it
   into a new Safari tab. Shared component: `apps/web/src/BackButton.tsx`.
5. It feeds lifetime stats: completed sessions materialize into `matches` /
   `match_participants`. Guests are skipped until linked to a member.
6. Live sync on every stat-mutating confirm (WebSocket hub, or the pack's own polling).
   Nobody should ever need to refresh.
7. Standalone playable without a crew or event where it makes sense: typed names, no stats.
8. Prefill rosters from the event's yes-RSVP list, and never clobber a session already in
   progress. Starting over a live session is confirm-and-replace, never silent.
9. Each pack tracks what is fun and easy about *that* game. We are not repeating tournament
   formats with different skins. Win tracking, repeatable interactivity, and stats that
   reflect that game's focus, without excessive manual entry.
10. Any pack with character selection ships a "Which game?" title selector that scopes both
    the picker and the random pool to that title's roster. Stats stay unified by character
    name across titles.
11. Randomization always stays within the game being played.

## Rules enforced by tests (breaking one fails the gate)
- **No em dashes anywhere**, in code, comments and UI copy. `copy-rules.test.ts` checks FOUR
  encodings (the literal character and the named, decimal and hex HTML entities), because a
  grep for the character alone misses one written as an entity in JSX and five shipped that
  way. It scans `.ts`, `.tsx`, `.css` and `.html`, so **markdown is on the honour system**:
  an em dash in `BACKLOG.md` or in this file breaks the rule without failing the gate.
  **The en dash and the middot are ALLOWED** and are doing jobs an em dash cannot: the en
  dash is the empty-value placeholder on the TV boards and the middot separates items in a
  line. The rule is about the em dash as punctuation in prose, not about non-ASCII
  typography.
- **A way back to the EVENT on every scoring screen.** `pack-screens.test.ts` lists them by
  name. The TV path is explicitly insufficient: `BackButton` is history-based and sends
  somebody who arrived from a shared link to home rather than the night. Beerio Kart is
  exempt as a vendored 1:1 replica.
- **No hardcoded colour literals outside the token blocks** in the main stylesheet, and no
  hardcoded Tailwind colour utilities. `TOKENISED_CSS` in `copy-rules.test.ts` names the
  files under this rule; a pack joins it on the commit that converts it.
- **Contrast pairs and identity assertions** per converted pack in `theme-contrast.test.ts`.
- **Retired ids are never reused for a different meaning** (retired modifier cards, the
  removed Salem roles), and a retired card without a display name fails a test.
- **Beerio Kart is permanently exempt from theming.**
- **`band.ts` fit metrics are never modified for aesthetic reasons.**

## Adding a game pack (read before writing a line of a new pack)
Rules 1 through 11 apply in full. These are the mechanical requirements on top.

**Server.** The pack gets ONE file, `apps/server/src/<pack>.ts`, calling
`createPackRuntime({ ...packConfig("<key>"), extras })` and keeping only what is genuinely
its own: its routes, its state shape, its `materialize*`, its `sessionView` body. Do not
write another `roleOf`, `loadState`, `saveState`, `ensureGame`, `ledgerKey` or
`deleteMaterialized`. Do not write another participant insert loop; call
`insertParticipants`. New session packs use `game_sessions` keyed `(eventId, pack)`;
`smash_sessions` is back-compat for one pack and is not a pattern to copy.

**Client.** The pack page is built on `usePackSession`, its TV view on `usePackLive`. Format
labels come from `formats.ts`. The picker entry goes in `packs.ts` and nowhere else. Data
reads go through `useCachedApi` except on TV routes, which are deliberately uncached.
Navigation uses `BackButton` and router links, never a raw `<a href>`.

**A casino pack is much less than the above**, because the engine, the money routes and every
money screen are shared: steps below shrink to a handful of callbacks, a `--cg-*` token block
and some copy. **A title-night pack is less still**: Board Game and Card Table share an
engine, every screen and every route, so a pack is a config object, a title list, a copy file
and a palette. `packages/shared/src/cardtable.ts` and `apps/server/src/cardtable.ts` are the
whole of a pack, about 50 lines each.

**Fixed constants that fail silently if you get them wrong.** `games.pack`, `games.name`, the
`game_sessions.pack` key, `ledgerKey`'s prefix, the `wsType` broadcast string, a modifier
`id` and a role `id`. Nothing errors when these are wrong: stats orphan, live sync goes dead,
or the pack's history splits across two leaderboard tabs. Pick them once, write them into the
shared pack map, and never change them afterward. APPEND registry entries; never insert above
a pack that is already live, because `SESSION_PACK_KEYS` feeds the event TV's tiebreak.

**Every pack ships with tests.** The pure decision logic (placement resolution, roster slot to
userId, guest versus member, series and rotation advance) gets `node:test` coverage in
`apps/server/tests/` or `packages/shared/tests/`. Anything needing Postgres is not unit-tested
here: extract the pure part and test that rather than stubbing Drizzle. **Capture fixtures by
RUNNING the unmodified engine before writing a line of a conversion.** Hand-written fixtures
have been wrong three times now, and a test written after a change pins whatever the change
broke.

**Registration checklist**, because a pack is not finished when its own file compiles:
1. `packages/shared/src/<pack>.ts` and the `WsEvent` union.
2. The two router mounts in `apps/server/src/index.ts`, TV router before the authed one.
3. `quickplay.ts`.
4. The `guest-link.ts` adapter table (`guestNames*` / `creditGuest*` / `rosterOf*`).
5. The two lazy routes in `App.tsx`, plus `prefetch.ts`.
6. `packs.ts`, the stats panel in `StatsPage.tsx`, the recap emoji in `recap.tsx`.
7. **Safe area:** nothing to do for the pack PAGE (index.css insets every shell
   structurally), but a TV screen setting its own `padding` must fold
   `env(safe-area-inset-*)` into its own `calc()`, because a class rule beats the
   zero-specificity shell inset. Casino packs get this free from `casino.css`.
8. **The browser harnesses, in the same commit that ships the screen.** `tv-fit.mjs` needs a
   payload and its cases; `theme-sweep.mjs` needs the page and TV routes in both `ROUTES` and
   `RULE_ROUTES`; `screens-baseline.mjs` needs a stub if the screen is worth pinning. THIS IS
   A STEP BECAUSE IT WAS MISSED FIVE TIMES. **The rule is about the SCREEN, not the pack:**
   any TV view joins both harnesses on the commit that ships it, whether it belongs to a
   pack, the shell or a vendored app, and a screen that predates this checklist is not
   exempt, it is overdue.

Miss one of these and the failure is quiet: the pack simply never appears on one screen, or
nobody ever measures it.

## Hosting and deploy
- GitHub is the source of truth. Push to `main` = auto-deploy on Render. Postgres is on
  **Neon** (Render's free database expires after 30 days; Neon's does not).
- **The schema is applied by the build.** The Render build command must end with
  `pnpm db:push:ci`. Full command:
  `corepack enable && pnpm install --prod=false && pnpm build && pnpm db:push:ci`
  (`--prod=false` is mandatory: Render sets `NODE_ENV=production`, which makes pnpm skip
  devDependencies, and the build needs vite/tsc/drizzle-kit.)

  when create/rename resolution wants a TTY). **A session cannot read the build log, so it
  cannot confirm this.** Any session shipping a schema change writes the idempotent SQL into
  its closeout unconditionally (`ALTER TABLE x ADD COLUMN IF NOT EXISTS ...`,
  `CREATE INDEX IF NOT EXISTS ...`), and James either confirms the drizzle-kit success line
  in the Render build log or runs that SQL in the Neon console.
- `RESEND_API_KEY` is set by hand in the Render dashboard and deliberately NOT declared in
  `render.yaml`, to avoid the silent-failure pattern.
- Free tier sleeps after 15 minutes idle. The keep-warm Action covers evening hours; warm it
  manually (`workflow_dispatch`) before an off-hours game night.
- Login codes and magic links print to the server logs in every environment as the delivery
  fallback.

## Hard-won environment knowledge (respect it)
- Express router-level middleware runs for every request entering the router, even without a
  route match. Public routers MUST mount before auth'd routers sharing a path prefix.
- Never cache `location` or `location.search` at module scope. Statically imported modules
  evaluate once at app boot against whatever URL loaded first. This silently froze the event
  id and killed Beerio prefill and stat reporting. **This is about values captured at import
  time, not about mutable runtime stores.**
- Same-route navigations (`/beerio` -> `/beerio?s=CODE`) do not remount the component. If a
  component reads its mode at mount, key it by `location.search`.
- Automatic redirects between two views of the same screen must REPLACE, not push. Pushing
  leaves a ghost history entry whose effect re-fires on back, producing a double-back bug.
  Firefox exposes it (no bfcache with an open WebSocket); Safari hides it.
- iOS Safari auto-zooms on any focused input under 16px and often does not zoom back out.
  Every input class is 16px for that reason. Do not add `maximum-scale`.
- An installed iOS PWA has a cookie jar separate from Safari's. A magic link tapped in Mail
  logs the session into Safari and leaves the installed app logged out. That is why the
  6-digit code is the primary path.
- Money is INTEGER CENTS everywhere, in state jsonb, in meta and on the wire. Dollars exist
  only at `parseCents` and `formatCents`. A zero-sum check in floating point reports a correct
  night as broken.
- Beerio bracket seeds are 1-BASED; the colors array is 0-based. Index with `seed - 1`.
- Guests carry no lifetime stats. A name that does not exactly match a crew member's display
  name is a guest, and silently dropping them was a real bug: report what was recorded. On a
  poker table the settlement counts guests and only the ledger WRITE skips them, or the
  balance check fires on a correct table.
- Session ledger keys are namespaced `{prefix}:{eventId}:{sessionKey}:{idx}`. Changing a
  generated key silently orphans existing rows. Legacy keys without `sessionKey` still exist
  and must keep resolving.
- Two placement rules live in this app and both are correct: a genuine TIE uses competition
  ranking (1, 1, 3) and a TEAM result ranks SIDES 1..N (a 2v2 is 1, 1, 2, 2). Unifying them
  would silently rewrite what a placement means in rows already written by the other rule.
- `side` is NULL when every side has one member, and it carries THREE different meanings
  where it is not: a competitive team (ping pong doubles, Mario Kart pairs, bracket team
  entrants), one co-op team holding the whole table (Casino Run), and a faction (Social
  Deduction). Only the first is "who you win with". A pack writing "a"/"b" for a 1v1 makes
  `meetingOutcome` classify two OPPONENTS as teammates, and the rivalry is wrong forever with
  nothing erroring.
- **Node 22 runs here and `pnpm test`, `pnpm -r typecheck` and `pnpm build` all really
  execute. Headless Chromium runs here too** (see Verification harnesses). Earlier sessions
  recorded "no node here" and later ones "no browser here"; both are obsolete.
- **Render's dashboard and build logs are NOT reachable from a session.** Do not claim a
  deploy succeeded, and do not ask to check one.
- GitHub's unauthenticated API rate-limits fast. Use `git clone --depth 1`.
- Changing a generated `ledgerKey`, a `wsType` string, a pack's display name, a modifier id
  or a role id all fail SILENTLY. None are caught by typecheck or build.
